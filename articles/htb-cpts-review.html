Cracking the HTB CPTS: My Journey, Exam Breakdown & Key Takeaways

Author: Asish K Sahadevan Published: 2026 Exam: Hack The Box CPTS Reading Time: 8 min

I recently completed and passed the Hack The Box Certified Penetration Testing Specialist (HTB CPTS) certification exam. In the offensive security community, CPTS has established itself as one of the most hands-on, realistic, and technically demanding enterprise penetration testing assessments available.

Key Insight: The CPTS exam moves far beyond simple flag capture. It is a full-scope corporate network engagement requiring structured methodology, multiple subnet pivots, deep Active Directory compromise, and delivery of a commercial-grade technical report.

1. Why CPTS Stands Apart

Unlike legacy 24-hour certification exams that simulate artificial time pressure, CPTS gives candidates 10 full days of continuous lab access, followed by a dedicated window for writing and submitting the assessment report.

  • True Multi-Tier Pivoting: The environment spans multiple non-routable subnets. Success requires fluid network routing using modern tooling rather than rudimentary port redirects.
  • Enterprise Active Directory Paths: Targets are organized into authentic domain trees and forests, requiring realistic enumeration with BloodHound, privilege delegation analysis, and trust exploitation.
  • The Report is Make-or-Break: Capturing flags only qualifies you for review; your final score depends on remediation guidance, CVSS 3.1 scoring, and step-by-step reproduction steps.

2. HTB Academy Preparation Path

The exam corresponds directly to the Penetration Tester job-role path on HTB Academy. Mastery of the following modules is essential:

  • Pivoting, Tunneling & Port Forwarding: Deep familiarity with ligolo-ng, chisel, SSH dynamic proxies, and SOCKS configuration.
  • Active Directory Enumeration & Attacks: AS-REP roasting, Kerberoasting, Unconstrained Delegation, ACL manipulation, and DCSync attacks.
  • Web Exploitation & File Inclusion: File upload bypasses, SQL injection, SSTI, and API authentication flaws.

3. Inside the Exam Experience

Phase 1: Initial Foothold & Perimeter Enumeration

Targeting exposed web interfaces revealed configuration oversights and parameter vulnerabilities. Scripting manual verification proved far more reliable than generic automated scanners.

Phase 2: Pivoting with Ligolo-ng

Once internal hosts were reached, setting up ligolo-ng TUN interfaces was a game-changer. It allowed direct subnet routing from the attacking system, enabling native execution of tools like nmap, netexec, and bloodhound-python without SOCKS proxy latency.

Phase 3: Active Directory Exploitation

BloodHound data collection pinpointed a non-obvious permission path to a Domain Admin equivalent account. Combining service ticket manipulation with misconfigured access controls led to full domain takeover.

4. Actionable Advice for Aspirants

  1. Rely on Ligolo-ng: Practice multi-level double and triple pivots before starting your exam timer.
  2. Screenshot Every Action: Capture output showing IP addresses (ipconfig / ifconfig), user context (whoami), and timestamps on the spot.
  3. Maintain a Sustainable Rhythm: Ten days allows for regular sleep, mental resets, and thorough documentation.
  4. Draft Findings Simultaneously: Write finding descriptions and reproduction steps as you discover them rather than waiting until the end.
